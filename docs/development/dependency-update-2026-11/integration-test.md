## 追補: sha2 0.11 / bzip2 0.6 への更新（#275）

PR #272 で見送った Linux 専用依存（AppImage 向け OpenH264 ランタイムのダウンロードで使用）の更新に伴う手動確認項目。

- Gherkin 対象外（挙動変更を意図しない依存更新）のため `@manual` シナリオは 0 件。以下は変更内容から導出した（追加観点）
- `openh264_fetch.rs` は新 API のままコンパイルでき、コード修正はしていない。bzip2 0.6 で既定バックエンドが C の bzip2-sys から純 Rust の libbz2-rs-sys に変わった
- 自動テスト済み: SHA256 の一致・不一致・大文字 hex、bzip2 の往復、不正入力でのエラー（`cargo test`）
- Linux（x86_64）で確認済み: Cisco 配布元から取得した `libopenh264-2.4.1-linux64.7.so.bz2` を一時テストで `verify_sha256`（既知ハッシュ）と `decompress_bz2` に通し、ハッシュ一致・1 バイト欠損で不一致・展開結果がシステムの `bzip2 -dc` の出力とバイト単位で一致することを確認した。AppImage での実操作は未実施

## 実施記録（2026-11-21、Linux）

PR #272 の「Linux 環境で確認が必要な項目」L1〜L8 を実施した。

### 実施条件

- Linux（Ubuntu、GNOME Wayland セッションのホスト）上で、隔離した Xvfb（X11、ウィンドウマネージャ無し）に `GDK_BACKEND=x11` で起動した。`XDG_DATA_HOME` / `XDG_CACHE_HOME` / `XDG_CONFIG_HOME` / `XDG_STATE_HOME` を一時ディレクトリへ隔離し、保存済みアカウントのデータのコピーを使用した（ログイン済み）。`dbus-run-session` でホストのセッションバスと分離した。
- 操作は XTest によるクリック・キー入力、確認はスクリーンショット・ウィンドウジオメトリ（xwininfo）・アプリの標準出力・WebKit リモートインスペクタ（`WEBKIT_INSPECTOR_HTTP_SERVER`）で行った。
- ビルド: L1・L2・L7・L8 は dev ビルド（`npm run tauri:dev`）、L3・L4・L6 は本ブランチからビルドした AppImage（updater-test の 0.8.6 / 0.8.7、FUSE で直接実行）。
- Wayland は未実施（ヘッドレスの Wayland コンポジタとスクリーンショット手段が無いため）。ウィンドウマネージャ無しのため、WM による配置・クランプに依存する挙動は未確認。

### 項目ごとの結果

- L1 起動と inject（No.6 相当の Linux 分）: OK。保存済みの 6 カラムが復元され X のタイムラインが表示された。各カラムで `window.__mcxI18n` が存在し、カラムヘッダの更新秒数・各ボタンが表示され、X の左サイドバーは非表示（inject 有効）。アプリの標準出力に panic / ERROR は無い。WebKit インスペクタでカラムのコンソールを確認し、既知のノイズ（通知カラムの `custom_css` の `appendChild` 例外、`ipc.localhost` の CSP 違反と postMessage へのフォールバック）以外に、全カラムで `Unhandled Promise Rejection: notification.is_permission_granted not allowed on window "column-..."` が出る。アプリの inject には該当呼び出しが無く、Tauri の notification プラグインが注入するスクリプト由来とみられる（依存更新前との比較は未実施）。その他は X 側の警告（`manifest-src` 未対応、`window.styleMedia` 非推奨、csp_report 400、試験中の再読込が多かったことによる 429）。
