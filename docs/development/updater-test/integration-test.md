# アプリ更新の試験の仕組み 手動テスト項目

自動テストで確認できない項目（実アプリでの画面遷移、実際のインストーラ実行・再起動、Android 実機での APK 更新）をまとめる。手順の詳細は [../updater-test-notes.md](../updater-test-notes.md) を参照。

## 自動テスト済みの範囲（手動では確認しない）

- モック種別ごとの確認結果・進捗通知・適用失敗、未指定・未知の値で本物の更新処理を使うこと（`src/services/mockUpdater.test.ts` / `updater.test.ts`）
- モック更新ありで起動するとダイアログが出て、更新を押すと進捗が出ること（`UpdateDialog.mockUpdater.test.tsx`）
- 配信サーバーの `latest.json`・リリース API の内容、配信対象外パスの拒否（`scripts/updater-test/manifest.test.ts` とプロパティテスト）
- 重ね設定の内容（`overlay.test.ts`）、本番設定が変わっていないこと（`productionConfig.contract.test.ts`）
- feature `updater-test` の有無による APK URL の許可・拒否（`src-tauri/src/commands/update.rs` のテスト。`cargo test --features updater-test` でも実行する）
- Windows で新版をビルドし、`release.json` の生成とサーバーからの `latest.json`・成果物の配信を確認済み（開発時に実施）

## 手動テスト項目

- No.4〜6（デスクトップの実更新）は普段使いのインストールを上書きし、データも共有する。試験後は GitHub Releases から正式版をインストールし直す（更新後のアプリは取得先が localhost のままのため）。
- No.7〜8（Android の実更新）は、正式版（リリース署名）が入っている端末では先にアンインストールが必要（データは失われる）。

## 実施記録（2026-11-21）

- Windows 11（`npm run tauri:dev`、WebView2 を CDP で操作）と Android エミュレータ Pixel_9（x86_64、debug と R8 リリース）で実施。実機 Android・Linux・macOS は未実施。
- Android で初回の更新試行時に 1 度 ANR が発生し、再起動後は再現しなかった（debug ＋ エミュレータの負荷が疑われる）。
