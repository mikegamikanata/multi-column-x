# 手動テスト項目: AppImage 再起動時に旧マウントの環境・fd を引き継がない（`relaunch_app`）

対象: 更新後の再起動と、OpenH264 有効化後の「今すぐ再起動」。どちらも `@tauri-apps/plugin-process` の `relaunch()` をやめ、自前の `relaunch_app` コマンド経由にした。

## 前提

- Linux AppImage の項目は、本ブランチからビルドした AppImage（`npm run tauri:build -- --bundles appimage`）で確認する。実 OS の FUSE マウントとプロセスの親子関係が必要なため CI では確認できない。
- Linux 項目は X11 / Wayland のどちらか、可能なら保存済みアカウントのコピーと XDG ディレクトリの隔離環境で行う。
- No.2 の自己更新は、署名済みの新旧 AppImage とローカル配信（`scripts/updater-test/`）が要る。PR #272 のマージ後に使える。

## 自動テスト済みの範囲（手動項目にしない）

- 環境整理の純粋関数（旧マウント配下の要素の除去、OpenH264 配置先の除去、空になった変数の削除、`APPDIR` / `APPIMAGE` / `ARGV0` / `OWD` / 初期化済み印の非継承、無関係な変数の引き継ぎ、`/tmp/.mount_abc` と `/tmp/.mount_abcd` の取り違え防止）の単体テストとプロパティテスト。
- 再起動方法の決定（AppImage 以外は従来経路、AppImage は `$APPIMAGE` を同じ引数で起動）、作業ディレクトリの決定（`OWD` あり / なし）。
- メインウィンドウ以外からの `relaunch_app` の拒否。
- 更新のインストール後に `updater` から、「今すぐ再起動」で `useH264Setup` から `relaunch_app` が呼ばれること。
- `spawn_detached` の fd 非継承・`setsid`・環境・作業ディレクトリ（Linux の `cargo test`）。
- ACL（`build.rs` / capability）の契約テスト。

## 実施記録（2026-11-21、Linux）

No.1 を Linux（Xvfb + X11、本ブランチから `npm run tauri:build -- --bundles appimage` でビルドした AppImage、保存済みアカウントのコピー、XDG 隔離）で実施し、OK だった。

- 再起動後、旧マウント `/tmp/.mount_run.AppjkgBk` は消え、新マウント 1 つだけになった。旧 runtime・旧本体プロセスは消滅した。
- 新 runtime・新本体・WebKitNetworkProcess・WebKitWebProcess の environ / fd / maps に旧マウント名は 0 件。fd 1023 は新マウントを指す（新 runtime 由来で正常）。
- 新本体の `LD_LIBRARY_PATH` は OpenH264 配置先 → 新マウントの順。`MULTI_COLUMN_X_LD_PATH_PRIMED=1` は新プロセス自身が付け直したもの。`OWD` は起動時の作業ディレクトリと一致した。新本体・新 runtime は別セッション（pgid=sid）。
- 再起動後に動画が再生でき、0:00 → 0:09 と進んだ。新アプリ終了で全プロセス・マウントが消えた。
- 修正前（同条件の実測）は、新プロセスの environ 10 変数に旧マウントが残り、新 runtime が旧マウントの fd 1023 を保持し、WebKitNetworkProcess が旧マウントの `gschemas.compiled` を mmap し、旧 runtime が新アプリ終了まで残っていた。
