# Android 動画ダウンロード（ポップアップのボタン・失敗の通知） 手動テスト項目

自動テストで確認できない項目（実機の WebView、X の実 DOM、保存先選択画面（SAF）、通信断、通知の表示、リリースビルドの ProGuard）をまとめる。設計と自動テストの範囲は [../android-notes.md](../android-notes.md) の「動画ダウンロード」節を参照。

自動テスト済み（ここでは扱わない）:

- ポップアップのボタンが、Android ではブリッジに長押しと同じ形の要求を送ること。押した後もボタンが押せること。未再生のときは再生を促すこと。送る手段が無いときはボタンを出さないこと。desktop では従来どおり `download_video` を呼ぶこと（`popup_toolbar.test.ts`）
- ポップアップのブリッジが、ダウンロード要求を長押しと同じ保存処理に渡すこと（`PopupSessionBridgeTest`）
- 失敗したら、開始前の失敗・HLS の音声だけの失敗も含めて失敗の通知を依頼し、その後に進捗の通知を終えること。成功時は依頼しないこと（`video_download.rs` の `finish_android_video_download`）
- 失敗の通知の ID・常駐しない設定（`VideoDownloadNotificationsTest`）、ja/en の文言（`StringResourcesTest`）

## 前提

- Android 端末（エミュレータ可）で X にログイン済み。
- 通知の権限（POST_NOTIFICATIONS）を許可している。許可が無い端末では、進捗の通知も失敗の通知も出ない（既存の割り切り）。
- 通信を切るには `adb shell "svc wifi disable; svc data disable"` を使い、確認後に `adb shell "svc wifi enable; svc data enable"` で戻す。
- Android のカラムには Tauri IPC が無いため、カラムの長押しメニューの「動画をポップアップで表示」からはポップアップが開かない（既存の制約）。ポップアップは、ツールバーのリンクのアイコン（URL をポップアップウィンドウで開く）から動画ツイートの URL を入れて開く。
