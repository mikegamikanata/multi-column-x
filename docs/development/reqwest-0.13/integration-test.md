# reqwest 0.13 更新 手動テスト項目

reqwest 0.12 → 0.13 の更新（Issue #273）に伴う手動確認項目。

- 変更点
  - 暗号プロバイダを ring に固定した（`rustls-no-provider` + `http_tls::configure_tls` で install）。
  - desktop の証明書検証を OS の証明書ストア（rustls-platform-verifier）に変更した。
  - Android は従来どおり同梱ルート証明書（webpki-root-certs）で検証する。
- 自動テスト済み（手動項目にしていない）
  - 暗号プロバイダ未設定の状態からのクライアント作成と、繰り返し作成
  - 同梱ルート証明書だけを信頼する設定でのクライアント作成と、証明書の件数
  - リダイレクト追従、エラーステータス、接続拒否、無通信タイムアウト
- ローカルで確認済み
  - `cargo check --target aarch64-linux-android`
  - aws-lc-rs が依存に無いこと（host と Android）
  - reqwest の重複解消
- 未検証（実機が必要）: 以下の全項目

## 実施記録（2026-11-21）

- Windows 11（`npm run tauri:dev`、WebView2 を CDP で操作）と Android エミュレータ Pixel_9（x86_64、debug と R8 リリース）で実施。実機 Android・Linux・macOS は未実施。
- Android で通信不可時の動画ダウンロード失敗はログ出力のみで、画面上の失敗表示や通知は無い（No.8 の期待結果との差。既存挙動）。
- Windows の更新確認で github.com への TLS 通信が成功した（OS 証明書ストア経由）。

## 実施記録（2026-11-21、Linux）

- Linux（Ubuntu、隔離した Xvfb・ウィンドウマネージャ無し・`GDK_BACKEND=x11`）で、本ブランチの AppImage を使って実施した。
- No.4: MP4 は desktop の導線（動画のポップアップ →「動画をダウンロード」→ GTK 保存ダイアログ）で保存でき、H.264 + AAC として読めた。HLS は `download_video` を直接呼び出して映像・音声の保存を確認した（HLS のみのポストを UI から操作する確認は未実施）。証明書・TLS エラーは無い。
- No.5: `gstreamer-openh264/` を削除した状態から取得でき、`libopenh264.so.7` が配置された。再起動後に動画が再生できた。
- No.6: OS の信頼ストアへの CA 登録と MITM プロキシが必要なため未実施。
