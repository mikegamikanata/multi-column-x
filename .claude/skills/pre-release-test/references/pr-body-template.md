# リリースPR本文のテンプレート

`pre-release-test` の Step 6 で、リリースPR（develop → main、タイトル `v<version>`）の本文をこの書式で作る。
`<...>` は置き換える。節の順番と見出しは変えない（リリースごとに同じ形で比較できるようにするため）。

```markdown
v<version> リリース

試験項目は [docs/release/pre-release-checklist.md](https://github.com/natsuyasai/multi-column-x/blob/<試験したコミットの完全なハッシュ>/docs/release/pre-release-checklist.md) を参照（手順・期待結果はリンク先）。

### 実施条件

- 比較範囲: `<前回タグ>..develop`

- 実施日: <YYYY-MM-DD>
- 実施者: <Claude による自動実施 / 人>（人が補った項目は備考に記載）
- Windows: <OS ビルド>、<リリースビルド / デバッグビルド>
- Android: <エミュレータ名・API レベル / 実機名>、<デバッグ APK / リリース署名 APK>
- Linux: <ディストリビューション / セッション種別>、<AppImage / deb>（未実施なら「未実施」）
```

## 書き方の注意

- 観点（要約）は 40 文字程度に縮める。手順・期待結果は本文に書かない（文字数上限のため）
- 備考は 1 行に収める。長い説明が要るものは「要確認事項」に回し、備考には `要確認 (a)` と書く
- 本文が 65,536 文字を超える場合は、「結果」節の `<details>` ごとに PR コメントへ移し、本文の「結果」節にはコメントへのリンクだけを残す
- 欠番の No. は表に載せない
